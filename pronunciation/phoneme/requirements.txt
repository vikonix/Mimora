# Dependencies for the pronunciation/phoneme/ module (text-only phoneme engine).
# Install on top of the project root requirements:
#   pip install -r pronunciation/phoneme/requirements.txt
#
# Most deps overlap with pronunciation/acoustic/ (transformers/torch/librosa for the wav2vec2
# recognizer, phonemizer-fork for the espeak reference). The one addition over the
# acoustic core is panphon, used for the articulatory feature distance.
#
# NOTE: phonemizer needs espeak-ng, and it is NOT a separate install any more.
# espeakng-loader (below) ships the shared library and its data as a wheel, and
# pronunciation/common/espeak.py registers both with phonemizer before the
# first phonemization. A system espeak-ng is now only the fallback. Do not rely
# on Kokoro/misaki registering it as an import side effect: Mimora's TTS
# backends import lazily, so a non-Kokoro run (Spanish on Supertonic) never
# imports Kokoro.

# >=5.3 closes CVE-2026-4372 (config-injection RCE); kept in sync with the
# application's own list in [project.dependencies] (pyproject.toml). The markers
# below relax torch/transformers on Intel macOS (x86_64) - see the Intel macOS
# note there. tools/check_markers.py checks both lists together.
transformers>=5.3; platform_system != 'Darwin' or platform_machine != 'x86_64'
transformers>=4.44,<5; platform_system == 'Darwin' and platform_machine == 'x86_64'
torch>=2.0.0; platform_system != 'Darwin' or platform_machine != 'x86_64'
torch==2.2.2; platform_system == 'Darwin' and platform_machine == 'x86_64'
librosa>=0.10.0
# Use phonemizer-fork, NOT plain "phonemizer" (shares the import namespace; the fork
# adds EspeakWrapper.set_data_path() that Kokoro/misaki rely on).
phonemizer-fork>=3.3.0
# The espeak-ng shared library and its data, as a wheel - see the NOTE above.
# The upper bound is not routine hygiene: the espeak-ng build inside this wheel
# IS the reference transcription this engine's calibration was fitted against
# (<lang>_model_calibration.json), so a version that transcribes differently
# moves every score with nothing to announce it. Kept in sync with
# pyproject.toml, where the full reasoning lives.
espeakng-loader>=0.2.4,<0.3
# Articulatory feature distance for the phoneme substitution cost (the one dep the
# acoustic core does not need).
panphon>=0.20.0
# transformers needs protobuf to parse the sentencepiece model when it builds the
# wav2vec2 phoneme (fast) tokenizer. Usually pulled in transitively, but pin it so
# a minimal standalone resolve does not fail with "requires the protobuf library".
# Kept in sync with pyproject.toml.
protobuf>=3.20.0
# Caps kept in sync with pyproject.toml: numba (via librosa, above) supports
# NumPy <= 2.4, so 2.5 breaks librosa at runtime - drop when numba supports 2.5.
# Intel macOS needs <2 for torch 2.2.2 (see the note above).
numpy>=1.24.0,<2.5; platform_system != 'Darwin' or platform_machine != 'x86_64'
numpy>=1.24.0,<2; platform_system == 'Darwin' and platform_machine == 'x86_64'
