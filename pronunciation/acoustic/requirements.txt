# Dependencies for the pronunciation/acoustic/ module (pronunciation analysis core).
# Reused from OpenPronounce (MIT). Install on top of the project root requirements.
#   pip install -r pronunciation/acoustic/requirements.txt
#
# NOTE: phonemizer needs espeak-ng, and it no longer has to be installed by
# hand. espeakng-loader (below) ships the shared library and its data as a
# wheel, and pronunciation/common/espeak.py registers both with phonemizer
# before this engine's first phonemization.
#
# A system espeak-ng remains a valid setup and is the fallback when the wheel
# is absent - install it and put it on PATH:
#   Windows : download the installer from https://github.com/espeak-ng/espeak-ng/releases
#             and set PHONEMIZER_ESPEAK_LIBRARY to the installed libespeak-ng.dll
#             plus PHONEMIZER_ESPEAK_DATA_PATH to its espeak-ng-data directory
#             (phonemizer's own search looks for espeak-ng.dll, which is not the
#             name the official installer writes)
#   macOS   : brew install espeak-ng
#   Linux   : sudo apt-get install espeak-ng

# >=5.3 closes CVE-2026-4372 (config-injection RCE); kept in sync with the
# application's own list in [project.dependencies] (pyproject.toml). The markers
# below relax torch/transformers/numpy on Intel macOS (x86_64) - see the Intel
# macOS note there. tools/check_markers.py checks both lists together.
#
# torchaudio is deliberately absent, and re-adding it breaks Linux: nothing
# imports it, while transformers imports it at module level whenever the
# environment merely has it installed, which fails when pip resolves torch and
# torchaudio to different CUDA series. The reasoning lives in pyproject.toml.
transformers>=5.3; platform_system != 'Darwin' or platform_machine != 'x86_64'
transformers>=4.44,<5; platform_system == 'Darwin' and platform_machine == 'x86_64'
torch>=2.0.0; platform_system != 'Darwin' or platform_machine != 'x86_64'
torch==2.2.2; platform_system == 'Darwin' and platform_machine == 'x86_64'
librosa>=0.10.0
scipy>=1.10.0
scikit-learn>=1.2.0
fastdtw>=0.3.4
# Use phonemizer-fork, NOT the plain "phonemizer" package: Kokoro/misaki call
# EspeakWrapper.set_data_path(), which exists only in the fork. Both packages share
# the "phonemizer" import namespace and must not be installed together, so installing
# plain phonemizer will break Kokoro. (from phonemizer import phonemize still works.)
phonemizer-fork>=3.3.0
# The espeak-ng shared library and its data, as a wheel - see the NOTE above.
# The upper bound is not routine hygiene: the espeak-ng build inside this wheel
# is the reference transcription the pronunciation scoring was calibrated
# against, so a version that transcribes differently moves scores with nothing
# to announce it. Kept in sync with pyproject.toml, where the reasoning lives.
espeakng-loader>=0.2.4,<0.3
python-Levenshtein>=0.21.0
soundfile>=0.12.0
# Cap kept in sync with pyproject.toml: numba (via librosa) supports NumPy
# <= 2.4, so 2.5 breaks librosa.resample at runtime. Drop when numba supports
# NumPy 2.5. Intel macOS needs <2 for torch 2.2.2 (see the note above).
numpy>=1.24.0,<2.5; platform_system != 'Darwin' or platform_machine != 'x86_64'
numpy>=1.24.0,<2; platform_system == 'Darwin' and platform_machine == 'x86_64'
